# Proteomics MCP v0.1.10

This was the version cited in the manuscript until 0.2.0. It fixes the problems found when the published package was checked end to end on the manuscript's public data ([#30](https://github.com/UadKLab/proteomics-mcp/issues/30)): every MCP tool and CLI command, on Linux, macOS and Windows, with Python 3.11 and 3.14. How scores, annotations and metrics are computed is unchanged: the manuscript's figures re-score identically from their stored payloads.

Install or upgrade:

```bash
pip install --upgrade proteomics-mcp==0.1.10
# or run it without installing:
uvx proteomics-mcp@0.1.10 --help
```

## Fixed

- **Static figures over MCP** ([#35](https://github.com/UadKLab/proteomics-mcp/issues/35)). Over MCP, `render_static_spectrum` failed on macOS, including in the Claude Desktop extension, and on Windows with a broken Tcl/Tk it aborted the whole server. Static SVG, PDF and PNG figures are now drawn without pyplot or any GUI backend, and no longer change matplotlib's global settings. Output is unchanged.
- **Error messages reach the agent** ([#27](https://github.com/UadKLab/proteomics-mcp/issues/27)). With mcp 2.3, MCP clients saw only *"Error executing tool"*. Errors the agent can act on now arrive with their type and message: a wrong path, an unsupported adapter, a malformed table or argument, an unknown field or peptide, an unreachable service. Internal errors stay hidden.
- **Generic adapter over MCP and the CLI** ([#38](https://github.com/UadKLab/proteomics-mcp/issues/38)). `adapter="generic"` always failed, because a column mapping could not be passed. Every tool and command that takes an adapter now accepts a JSON column-mapping file (`column_mapping_path` / `--column-mapping`); see `docs/reference.md`.
- **Scored tables join renamed candidate tables** ([#39](https://github.com/UadKLab/proteomics-mcp/issues/39)). Joining a scored table matched nothing, silently, when the candidate table had been renamed. This is the case for the FragPipe table in the manuscript's Zenodo record. Rows whose `candidate_id` is not found now join on run + scan + peptidoform, one to one only; ambiguous rows are left unmatched. Tools report the join (`scored_join`), with a warning when nothing matched or rows were ambiguous.
- **SDRF from PRIDE** ([#40](https://github.com/UadKLab/proteomics-mcp/issues/40)). `retrieve_pride_sdrf` searched only the first 100 files of a project and could not download what it found. It now pages through the whole listing (e.g. PXD014877, PXD010595), prefers a named `*.sdrf.tsv`, and downloads over HTTPS.
- **Precursor m/z of USI spectra** ([#41](https://github.com/UadKLab/proteomics-mcp/issues/41)). Spectra retrieved from PRIDE by USI had no precursor m/z, so USI-based scores lacked `precursor_signal_fraction`. The precursor m/z is now read from the PROXI response; other metrics are unchanged.
- **Batch rendering manifests** ([#45](https://github.com/UadKLab/proteomics-mcp/issues/45)). `render_spectra_batch` now reads JSON Lines and gzip-compressed manifests, not only JSON.
- **Batch status** ([#46](https://github.com/UadKLab/proteomics-mcp/issues/46)). The status of a prediction or scoring batch can now be read while it runs and after an interruption (`seconds_since_update`). Before, it could be read only once the batch had finished. Results are still written at the end, so an interrupted batch must be run again.

## Added

- **Predictor version in every prediction and score** ([#22](https://github.com/UadKLab/proteomics-mcp/issues/22)): the installed MS2PIP release (e.g. `4.2.0`), or the Koina model and version (e.g. `Prosit_2020_intensity_HCD@1`).
- **Client setup guide** ([#53](https://github.com/UadKLab/proteomics-mcp/issues/53)): `docs/clients.md` for Claude Desktop, Claude Code, Codex CLI, Cursor and Windsurf.
- **End-to-end tests on public data** (`tests/e2e`, `e2e.yml`, [#30](https://github.com/UadKLab/proteomics-mcp/issues/30)). They run the package from PyPI against the Zenodo supplement, PRIDE spectra by USI, an OpenMS mzML, a PRIDE MGF and a timsTOF run. They re-score every figure PSM with live MS2PIP and Koina, and run the batch workflow.

## Changed

- **Documentation:**
  - USI spectra can differ from local conversions of the same scan; PRIDE returned fewer peaks for 23 of the 25 reference PSMs.
  - `uvx proteomics-mcp@X.Y.Z` is the pinning form.

## Reproducing the manuscript

The figures were made with proteomics-mcp 0.1.8 and MS2PIP 4.1.2.

- **Exact reproduction:** with `pip install proteomics-mcp==0.1.10 ms2pip==4.1.2` (Python 3.11–3.13; MS2PIP 4.1.2 has no Python 3.14 wheels), all 25 PSMs shown in Figures 2 and 3 and Supplementary Figures 1, 2 and 5 re-score exactly as stored, mass errors included.
- **With MS2PIP 4.2.0** (the default since 0.1.9), on the same 25 PSMs:
  - matched and predicted ion counts are identical;
  - spectral angle, cosine and Pearson differ by at most 2×10⁻⁷;
  - fragment mass errors shift by up to 0.18 ppm, because MS2PIP 4.2.0 corrected the predicted fragment m/z by about 4.6×10⁻⁵ Da. Figure 2's fragment absolute mass error becomes 15.864 ppm instead of 15.822 ppm ([#23](https://github.com/UadKLab/proteomics-mcp/issues/23)).
- **Figure 4** depends on its input tables being re-deposited ([#42](https://github.com/UadKLab/proteomics-mcp/issues/42)).
