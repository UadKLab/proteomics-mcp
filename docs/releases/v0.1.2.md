# proteomics-mcp v0.1.2

This release tightens the agent-facing batch workflow rather than broadening the biological surface area. The main change is that long-running prediction, scoring, and rendering jobs now expose stable progress artifacts that an MCP client or coding agent can poll without retransmitting large payloads or waiting on silent calls.

## What is new

### 1. Batch prediction progress

`build-prediction-batch` now writes a persistent status file alongside the existing manifest, mapping, fragment, and failure artifacts.

You can inspect it through:

- `inspect-prediction-batch-status`

This makes long MS2PIP prediction runs easier to orchestrate from MCP clients and agents.

### 2. Batch scoring progress

`score-from-prediction-batch` now writes a persistent scoring status file and exposes it through:

- `inspect-scored-batch-status`

This is the main improvement for workflows that score larger candidate subsets against local Feather spectra.

### 3. Progress support for other heavy local workflows

Two other long-running paths now support the same pattern:

- `score-candidates --status-path ...`
- `render-spectra-batch --status-path ...`

`render-spectra-batch` also writes a default `render_batch_status.json` in the output directory when no explicit path is supplied.

### 4. Batch rendering contract remains file-first

The batch renderer keeps the current file-backed input model:

- `input_path` for realistic workloads
- inline `items` for small/debug calls
- `validate_only=true` for schema checks before expensive rendering

This preserves the minimal MCP style of the package while reducing tool-call fragility for large spectra.

## Quick start

Build a prediction batch, then poll status:

```bash
uv run proteomics-mcp build-prediction-batch \
  --path predictions.csv \
  --output-prefix results/pred_batch \
  --adapter instanovo \
  --predictor-backend ms2pip \
  --ms2pip-model HCD

uv run proteomics-mcp inspect-prediction-batch-status \
  --manifest-path results/pred_batch_prediction_manifest.json
```

Score against local spectra, then poll scoring status:

```bash
uv run proteomics-mcp score-from-prediction-batch \
  --manifest-path results/pred_batch_prediction_manifest.json \
  --spectra-path spectra.feather \
  --output-prefix results/pred_batch

uv run proteomics-mcp inspect-scored-batch-status \
  --manifest-path results/pred_batch_scoring_manifest.json
```

## Important caveats

- This release improves orchestration and polling, not the underlying scoring formulas.
- `bruker-d-to-feather` is unchanged in this release; it still does not expose the same fine-grained progress surface because most runtime sits inside AlphaTims or fallback conversion.
- The project is still distributed through GitHub releases only; there is no PyPI publishing yet.

## Validation status

Release preparation included:

- full test-suite execution with `uv run pytest`
- package build validation with `uv build`
- CLI entrypoint validation with `uv run proteomics-mcp --help`

## Who should use this release

This release is useful if you want to:

- run larger batch prediction/scoring jobs under MCP control
- poll deterministic status files from an agent or external workflow
- avoid embedding large spectrum payloads inline in tool calls
