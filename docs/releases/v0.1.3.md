# proteomics-mcp v0.1.3

This release strengthens the MCP semantic layer rather than changing the underlying scoring or visualization engine. The main goal is better agent usability: clearer tool discovery, typed arguments, and less ambiguity around what each tool expects.

## What is new

### 1. Typed MCP arguments across the exposed surface

The MCP server no longer exposes the main workflows through broad `options_json` argument blobs.

Instead, the public tools now declare typed parameters directly for:

- table inspection
- summary and binning utilities
- spectrum scoring
- batch prediction and batch scoring
- spectrum rendering
- dataset aggregation

This improves agent-side tool selection and argument construction.

### 2. Better tool descriptions

The MCP wrappers now include short task-oriented descriptions for all exposed methods.

That gives MCP clients and LLM agents better discovery text for:

- when to use a tool
- what kind of input it expects
- what sort of output it returns

### 3. Stronger semantic resources

A new MCP resource, `method://tooling_surface_v1`, documents the overall structure of the server:

- inspection tools
- summary tools
- rendering tools
- batch orchestration tools
- conversion/export tools
- targeted spectrum evidence tools

This complements the existing schema and method resources.

### 4. Public surface cleanup without core workflow churn

The underlying workflow functions remain stable. The change is concentrated in the MCP facade, so the release improves discoverability without changing the core proteomics logic.

## Quick start

Start the MCP server from a client as usual:

```json
{
  "mcpServers": {
    "proteomics-mcp": {
      "command": "uv",
      "args": ["run", "proteomics-mcp", "serve"],
      "cwd": "<repository checkout directory>"
    }
  }
}
```

Then call tools with explicit arguments instead of an `options_json` wrapper, for example:

- `inspect_psm_table(path=..., adapter=..., scored_path=..., limit=...)`
- `score_spectrum(candidate=..., observed=..., tolerance=0.05, annotation_ion_types="by")`
- `render_spectra_batch(input_path=..., output_dir=..., views=["comparison","annotated","observed"])`

## Important caveats

- This release improves the MCP contract and discovery experience; it does not change the underlying scoring formulas.
- Older clients or scripts that assumed the MCP server accepted `options_json` for the main tools should be updated to use the typed arguments now exposed by the server.
- The project is still distributed through GitHub releases only; there is no PyPI publishing yet.

## Validation status

Release preparation included:

- full test-suite execution with `uv run pytest`
- targeted verification of the MCP wrapper layer
- package build validation with `uv build`
- CLI entrypoint validation with `uv run proteomics-mcp --help`

## Who should use this release

This release is useful if you want to:

- use `proteomics-mcp` from an LLM agent or MCP-capable client
- reduce ambiguity in tool discovery and argument selection
- keep the existing proteomics workflows while exposing a clearer semantic surface
