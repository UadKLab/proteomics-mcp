# proteomics-mcp v0.1.5

This release moves the MCP server onto the Python SDK v2 line while keeping the proteomics workflows and rendered outputs stable.

The main user-facing result is straightforward:

- the server now targets the current MCP SDK/protocol generation
- existing CLI behavior stays the same
- example spectrum HTML outputs remain unchanged

## What is new

### 1. MCP SDK v2 migration

`proteomics-mcp` now targets:

- `mcp>=2,<3`
- the MCP `2026-07-28` protocol line through the Python SDK v2 implementation

For this repository, the migration is intentionally narrow. The change is in the MCP wrapper layer rather than the scoring, annotation, visualization, or table-inspection core.

### 2. Stable rendered spectrum outputs after migration

The migration was checked against the existing TDYMVGSYGPR example set.

Mirror, annotated, and observed-only HTML outputs were regenerated and compared against the checked-in examples. The outputs matched byte-for-byte when rendered with the same annotation settings.

### 3. Documentation updated for current MCP usage

The MCP integration docs now reflect that the package targets the SDK v2 line while keeping the same local stdio operating model:

- configure a local stdio MCP server
- let the client launch `proteomics-mcp serve`
- use the same exposed tool surface as before

### 4. Extension manifest version corrected

The Claude Desktop extension manifest version is now aligned with the package release version instead of lagging behind the Python package version.

## Quick start

Update the local environment:

```bash
uv sync
uv run pytest -q
uv run proteomics-mcp --help
```

Your existing stdio MCP client configuration can stay the same:

```json
{
  "mcpServers": {
    "proteomics-mcp": {
      "command": "uv",
      "args": ["run", "proteomics-mcp", "serve"],
      "cwd": "/absolute/path/to/proteomics-mcp"
    }
  }
}
```

## Important caveats

- This release does not add new proteomics functionality by itself; it updates the MCP server dependency line and protocol compatibility layer.
- The migration assumes the MCP client can work with the current Python SDK v2 line. For the local stdio workflow used here, that is the main compatibility surface to verify.
- The temporary regression-render folder used during migration verification is not part of the release payload.

## Validation status

Release preparation included:

- full test execution with `uv run pytest`
- CLI sanity verification through `uv run proteomics-mcp --help`
- render-regression verification against the existing TDYMVGSYGPR HTML examples

## Who should use this release

This release is useful if you want to:

- keep `proteomics-mcp` aligned with the current MCP Python SDK line
- use the existing local stdio MCP setup without changing your proteomics workflows
- keep rendered spectrum outputs and existing examples stable while updating the MCP layer
