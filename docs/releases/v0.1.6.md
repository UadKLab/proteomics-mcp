# proteomics-mcp v0.1.6

`proteomics-mcp` is a local-first MCP server and Python package for inspecting proteomics identification tables and interrogating selected MS2 spectra. This release adds model-aware remote fragment prediction through Koina and improves support for labelled InstaNovo multi-run outputs.

## What is new

- Koina is available as a fragment-prediction backend alongside local MS2PIP and the test-only mock backend.
- `Prosit_2020_intensity_HCD` can be used through Koina for targeted spectrum scoring and reusable prediction batches.
- `describe_predictor_model` is available in the CLI and MCP. It retrieves the live Koina model schema before inference, allowing agents to check required inputs and outputs.
- Koina requests are built from the advertised schema rather than a fixed payload. Invalid fragment placeholders are removed, cached predictions are marked as cache hits, and default fragment charges follow `<= precursor charge - 1`.
- Koina batch failures now finish with persistent failure rows and status artifacts instead of aborting before batch inspection is possible.
- Labelled InstaNovo `*_PSM` exports now preserve the run key from `sample` and correctly convert their zero-based `spectrum_index` to the corresponding mzML scan number.

## User-facing changes

Use Koina/Prosit from the CLI:

```bash
uv run proteomics-mcp predict-fragments \
  --backend koina \
  --model Prosit_2020_intensity_HCD \
  --peptidoform PEPTIDE \
  --charge 2
```

Inspect a remote model before a large batch:

```bash
uv run proteomics-mcp describe-predictor-model \
  --model Prosit_2020_intensity_HCD
```

The README now focuses on installation and normal usage. Client configuration and deployment guidance are consolidated in `docs/reference.md`.

## Important limits

- Koina is a remote service. Local MS2PIP remains the offline option.
- The wrapper supports the Koina inputs currently used by common fragment predictors: peptide sequence, precursor charge, collision energy, fragmentation type, and instrument type. A model requiring other mandatory inputs is reported as unsupported before inference.
- The wound-fluid PD workbook and the supplied 2019 HYC/MEC mzMLs are separate inputs; only the new labelled InstaNovo CSV is paired to the HYC/MEC runs.
