# Proteomics MCP v0.1.9

This is the first release built and published to PyPI by the automated release workflow (Trusted Publishing). It contains packaging, CI and documentation fixes only. Adapters, scoring, annotation, metrics and rendering are unchanged from v0.1.8, the version cited in the manuscript.

Install or upgrade:

```bash
pip install --upgrade proteomics-mcp==0.1.9
# or run it without installing:
uvx proteomics-mcp@0.1.9 --help
```

## Fixed

- **Claude Desktop extension on Python 3.14** ([#21](https://github.com/UadKLab/proteomics-mcp/issues/21)). The v0.1.8 `.mcpb` failed to start when uv picked Python 3.14: the locked `ms2rescore-rs` 0.4.3 has no Python 3.14 wheel, and the source build fails. The bundle now pins Python 3.12 (`.python-version`) and locks `ms2pip` 4.2.0 / `ms2rescore-rs` 0.6.0. **v0.1.8 extension users:** install this release's `.mcpb`. If you have to stay on v0.1.8, make Python 3.12 available and set `UV_PYTHON=3.12` for Claude Desktop.
- **Server version.** MCP `initialize` now reports the package version; it was an empty string.
- **MS2PIP on macOS without Homebrew `libomp`.** It now fails with an actionable error, *"install it with `brew install libomp`"*, instead of a raw `XGBoostError`. The error message also reaches MCP clients.
- **Source distribution.** The sdist ships the complete `tests/` directory, so its tests run against the installed wheel.

## Changed

- **MS2PIP 4.2.0** in the locked environment used by the Claude Desktop extension (previously 4.1.2); fresh `pip` installs already resolved 4.2.0. On the `examples/22_hela_instanovo_top5` PSMs:
  - Predictions are bit-identical for 2+ precursors.
  - For 3+ precursors (`HCDch2`), intensities shift slightly, and spectral angle, cosine and Pearson change by less than 1e-7. Explained intensity and matched ions are unchanged.

  See [#23](https://github.com/UadKLab/proteomics-mcp/issues/23).
- **Project metadata on PyPI:**
  - authors from `CITATION.cff`
  - classifiers for Python 3.11–3.14, `Development Status :: 4 - Beta` and `Intended Audience :: Science/Research`
  - SPDX licence with `license-files`
  - a Changelog URL
- **Dependency:** dropped the unused `typer`.
- **Documentation:**
  - README and docs lead with `pip install proteomics-mcp` / `uvx proteomics-mcp serve`, and list the platform requirements.
  - The docs and `PRIVACY.md` state that MS2PIP downloads its model files once, on first use (from `genesis.ugent.be`, with a Zenodo fallback).

## Added

- **Release workflow:** on tag push it runs build → verify on Linux, macOS and Windows with Python 3.11–3.14 → TestPyPI → PyPI → GitHub release, using Trusted Publishing with attestations.
- **CI** tests the built wheel instead of the source tree, plus the Claude Desktop extension launch command.
- **Release tooling:** a version consistency check, a wheel contents check, an MCP stdio smoke test, `RELEASING.md` and `CHANGELOG.md`.

## Platform requirements

- Python 3.11, 3.12, 3.13 or 3.14.
- Linux x86-64: glibc 2.28 or newer; Python 3.13 and 3.14 need glibc 2.34 or newer (`pyopenms` wheels).
- macOS: Apple silicon needs macOS 14 or newer. Intel Macs need macOS 13 or newer and Python 3.11–3.13.
- Windows x86-64.

## Known issues

- **Tool error messages are hidden from MCP clients with `mcp` ≥ 2.3** ([#27](https://github.com/UadKLab/proteomics-mcp/issues/27)). Fresh `pip`/`uvx` installs get `mcp` 2.3, which shows clients only *"Error executing tool <name>"* for unexpected errors, such as a wrong file path or adapter. The reason is still written to the server log. The `libomp` error above is passed through. The Claude Desktop extension uses the locked `mcp` 2.0 and is not affected.
- **MS2PIP on macOS needs `brew install libomp`.** Without it, MS2PIP prediction tools report an error asking you to install it; all other tools work.

The full list of changes is in [CHANGELOG.md](https://github.com/UadKLab/proteomics-mcp/blob/main/CHANGELOG.md).
