# Proteomics MCP v0.2.0

This is the version cited in the manuscript. It carries the correctness fixes found in the co-author review ([#33](https://github.com/UadKLab/proteomics-mcp/issues/33), [#149](https://github.com/UadKLab/proteomics-mcp/issues/149)), and **it changes scientific output**: scores, annotations and figure values differ from 0.1.x. The manuscript's figures are regenerated with this release. `metric_profile = "legacy_v1"` in a configuration file scores as 0.1.10 and earlier did, but it does not undo the fixes to how tables are read; see [Reproducing the manuscript](#reproducing-the-manuscript).

Install or upgrade:

```bash
pip install --upgrade proteomics-mcp==0.2.0
# or run it without installing:
uvx proteomics-mcp@0.2.0 --help
```

## Breaking changes

Check these before upgrading a pipeline from 0.1.x:

- **Score fields** ([#51](https://github.com/UadKLab/proteomics-mcp/issues/51)): `xcorr` and `hyperscore` are now the engines' scores, on a different scale. `log10_xcorr`, `log2_xcorr` and `log2_hyperscore` no longer exist under either profile. Under `legacy_v1` the 0.1.x variants are renamed `xcorr_like`, `log10_xcorr_like`, `log2_xcorr_like`, `hyperscore_like` and `log2_hyperscore_like`. Dataset and dashboard columns follow (`best_xcorr`, `xcorr_mean`).
- **Default metric profile `v2`** ([#72](https://github.com/UadKLab/proteomics-mcp/issues/72), [#74](https://github.com/UadKLab/proteomics-mcp/issues/74), [#83](https://github.com/UadKLab/proteomics-mcp/issues/83)): spectral angle, cosine, Pearson, matched-ion counts and explained intensity change for most PSMs.
- **Casanovo confidence** ([#157](https://github.com/UadKLab/proteomics-mcp/issues/157)):
  - Casanovo's own peptide score (`peptide_score` or `search_engine_score[1]`) becomes a confidence only for Casanovo 5.x, given with the new `casanovo_version` option. A 4.x score, or a score without a version, gets no confidence and a warning.
  - A `log_probs` column with values above 0 is refused.
  - A `log_probs` value of 0 now gives confidence 1, not 0.
- **Row caps of the inspect tools** ([#82](https://github.com/UadKLab/proteomics-mcp/issues/82)): `inspect_psm_table(limit=N)` and `inspect_peptide_table(limit=N)` now read the whole table, and `limit` sets only the number of preview rows. Use the new `max_rows` to cap the rows read.
- **Spectrum lookup is strict** ([#76](https://github.com/UadKLab/proteomics-mcp/issues/76)): a run name that matches no run of a multi-run spectrum table, or a scan number that matches several different spectra, is an error. Before, the first spectrum with that scan number was returned.
- **`mcp>=2.1`** is required ([#164](https://github.com/UadKLab/proteomics-mcp/issues/164)).

## Changed (scores)

- **XCorr and hyperscore are Comet's and X! Tandem's** ([#51](https://github.com/UadKLab/proteomics-mcp/issues/51)). Under metric profile `v2`, `xcorr` is Comet 2026.01.1's XCorr (presets `high_res` and `low_res`) and `hyperscore` is X! Tandem 2015.12.15.2's. Both were checked against the engines themselves: 3,128 PSMs reproduce exactly (`validation/engine_scores/`, [#154](https://github.com/UadKLab/proteomics-mcp/pull/154)). Under `legacy_v1` the 0.1.x variants remain, renamed `xcorr_like`, `log10_xcorr_like`, `log2_xcorr_like`, `hyperscore_like` and `log2_hyperscore_like`. `log10_xcorr`, `log2_xcorr` and `log2_hyperscore` no longer exist under either profile.
- **Spectral angle, cosine and Pearson compare every predicted ion** ([#72](https://github.com/UadKLab/proteomics-mcp/issues/72)). Unmatched ions count with zero observed intensity. Metric profile `v2` is now the default.
- **Predicted-ion cut-off** ([#83](https://github.com/UadKLab/proteomics-mcp/issues/83)): ions below 0.1% of the strongest predicted ion are not scored (`min_predicted_intensity`).
- **One observed peak explains at most one predicted ion** ([#74](https://github.com/UadKLab/proteomics-mcp/issues/74)).
- **Precursor mass error from the spectrum, for every engine** ([#179](https://github.com/UadKLab/proteomics-mcp/issues/179)). `precursor_mass_error_*` and `precursor_isotope_error` use the spectrum's precursor m/z, as they already did for de novo results; the engine's own (recalibrated) error is reported separately as `engine_precursor_isotope_error` and `engine_precursor_mass_error_ppm`. MaxQuant PSMs showed about 0 ppm before, because msms.txt's `m/z` is the peptide's theoretical m/z. The isotope correction now goes up to +3, as in the supplement's FragPipe search.
- **Supplied predictions follow the package's own rules, and results record what was scored** ([#137](https://github.com/UadKLab/proteomics-mcp/issues/137)): `scored_ions`, `excluded_predicted_ions`, `metric_n` and `scoring_settings`.

## Fixed

- **Peptides and masses:**
  - modification parsing in every adapter ([#75](https://github.com/UadKLab/proteomics-mcp/issues/75));
  - MaxQuant fixed modifications ([#101](https://github.com/UadKLab/proteomics-mcp/issues/101));
  - Proteome Discoverer Met-loss ([#125](https://github.com/UadKLab/proteomics-mcp/issues/125));
  - notation normalised in the generic adapter and in accuracy targets ([#124](https://github.com/UadKLab/proteomics-mcp/issues/124));
  - the precursor mass error now includes every modification ([#73](https://github.com/UadKLab/proteomics-mcp/issues/73));
  - w-ion masses and C-terminal residues ([#79](https://github.com/UadKLab/proteomics-mcp/issues/79));
  - precursor-related ions carry every modification ([#174](https://github.com/UadKLab/proteomics-mcp/issues/174)).
- **Spectra and joins:**
  - spectrum lookup never returns another spectrum ([#76](https://github.com/UadKLab/proteomics-mcp/issues/76));
  - timsTOF scan numbers and mobility ([#95](https://github.com/UadKLab/proteomics-mcp/issues/95));
  - mzML isolation window and injection time ([#77](https://github.com/UadKLab/proteomics-mcp/issues/77));
  - one run-matching rule ([#142](https://github.com/UadKLab/proteomics-mcp/issues/142));
  - gzipped run names ([#126](https://github.com/UadKLab/proteomics-mcp/issues/126));
  - the metadata join reports what it matched ([#146](https://github.com/UadKLab/proteomics-mcp/issues/146));
  - USI spectra carry their retention time ([#135](https://github.com/UadKLab/proteomics-mcp/issues/135));
  - USI retrieval honours its timeout ([#84](https://github.com/UadKLab/proteomics-mcp/issues/84)).
- **Adapters and tables:**
  - InstaNovo 1.0–1.2 output formats ([#107](https://github.com/UadKLab/proteomics-mcp/issues/107));
  - tab-separated and compressed tables ([#140](https://github.com/UadKLab/proteomics-mcp/issues/140));
  - Casanovo scores are read by what their column holds ([#157](https://github.com/UadKLab/proteomics-mcp/issues/157));
  - inspect tools and row caps ([#82](https://github.com/UadKLab/proteomics-mcp/issues/82));
  - InstaNovo export ([#80](https://github.com/UadKLab/proteomics-mcp/issues/80));
  - multiplexed SDRF ([#81](https://github.com/UadKLab/proteomics-mcp/issues/81)).
- **Predictions:** Koina uses the spectrum's collision energy, or one given per call ([#128](https://github.com/UadKLab/proteomics-mcp/issues/128)).
- **Histograms count their maximum** ([#169](https://github.com/UadKLab/proteomics-mcp/issues/169)). Histograms whose range came from the data left out the values at the maximum; the published Figure 4 dashboard plots 98–99 of its 100 PSMs.
- **One-sided bin ranges** ([#175](https://github.com/UadKLab/proteomics-mcp/issues/175)). `bin_numeric_field` ignored `range_min` or `range_max` given on its own; either end can now be given alone.
- **Unexpected errors stay hidden from MCP clients** ([#164](https://github.com/UadKLab/proteomics-mcp/issues/164)). The package now requires `mcp>=2.1`; 2.0.x passed internal error text, such as file paths, to the client.
- **HTML escaping** ([#78](https://github.com/UadKLab/proteomics-mcp/issues/78)) and **faster peptide summaries** ([#68](https://github.com/UadKLab/proteomics-mcp/issues/68)).

## Added

- **Validation against Comet and X! Tandem** (`validation/engine_scores/`): BioContainers images pinned by digest, committed inputs and golden output, a one-command rerun, and a weekly workflow.
- **Isotope-corrected precursor error** and **per-candidate `warnings`**.
- **Tests against independent references** ([#179](https://github.com/UadKLab/proteomics-mcp/issues/179)): masses against pyteomics, against the engines' reported masses and errors, and scoring invariants.

See [`CHANGELOG.md`](https://github.com/UadKLab/proteomics-mcp/blob/main/CHANGELOG.md) for the details of every change.

## Reproducing the manuscript

- **Figures:** regenerated with this release and MS2PIP 4.1.2 (pinned only in the figure environment, [#23](https://github.com/UadKLab/proteomics-mcp/issues/23)), by `scripts/regenerate_figures.py`; see `RELEASING.md`. Figure 2 becomes:

  | Value | 0.1.x | 0.2.0 |
  |---|---|---|
  | Spectral angle | 0.833 | 0.834 |
  | Pearson | 0.962 | 0.960 |
  | Matched ions | 22/24 | 18/18 |
  | Explained intensity | 48.0% | 47.1% |
  | XCorr (Comet) | log2 XCorr variant 18.765 | 3.336 |
  | Hyperscore (X! Tandem) | log2 hyperscore variant 5.983 | 59.5 |
  | Fragment abs error | 15.822 ppm | 2.796 ppm |

- **Figure 4:** rebuilt from the first 100 PSMs in the deposited FragPipe PSM table, retained in source-file order ([#42](https://github.com/UadKLab/proteomics-mcp/issues/42), [#47](https://github.com/UadKLab/proteomics-mcp/issues/47)).
- **Zenodo:** a new version of the supplement carries the regenerated figures, tables and payloads, the Figure 4 spectra, `CHANGES.md` and `PROVENANCE.md`.
- **The published (0.1.x) values:** `metric_profile = "legacy_v1"` gives the 0.1.x scores for the same peptidoform, spectrum and prediction. Re-scoring the stored payloads reproduces the published values, with XCorr and hyperscore under their `*_like` names; the e2e rescoring test checks this. Fragment mass errors also need `ms2pip==4.1.2` ([#23](https://github.com/UadKLab/proteomics-mcp/issues/23)).
- **Re-reading the supplement's tables** does not reproduce them under either profile. The fixes to how tables are read change some peptidoforms, and so their scores:
  - [#101](https://github.com/UadKLab/proteomics-mcp/issues/101): MaxQuant fixed modifications are applied. The Figure 3B PSM `AQNSCPICQK` becomes `AQNSC[UNIMOD:4]PIC[UNIMOD:4]QK`, and 5,966 of the 22,782 ProteomeTools PSMs contain cysteine.
  - [#75](https://github.com/UadKLab/proteomics-mcp/issues/75): 503 of the 52,530 FragPipe PSMs change modification.
  - [#125](https://github.com/UadKLab/proteomics-mcp/issues/125): 19 Proteome Discoverer PSMs get corrected modification sites.
  - [#79](https://github.com/UadKLab/proteomics-mcp/issues/79): annotations with w ions change.
